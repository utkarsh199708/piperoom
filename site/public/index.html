05 — Trust

It can read. It can't write.

Piperoom is built so Claude can be in the room without being able to touch the pipeline. Each guarantee names the file on main that enforces it.

T1

Read-only by construction

Every investigation tool sits in a read-only registry that refuses anything else. Client interfaces are split into readers and writers, and writes live only in a separate set of actions. Source Postgres reads run in a READ ONLY transaction that is rolled back. Every read and every action is checked against the room's own pipeline.

Proof: internal/tools/tool.go · internal/clients/postgres · internal/tools/scope.go

T2

Approval per layer, bound to the exact plan

Each step names its layer, and the approver must own that layer. The approval carries a SHA-256 fingerprint of the proposal: without it the server answers 400, with a different one 409 params_mismatch. Each write action has a preview and a rollback.

T3

Secrets masked, untrusted text kept as data

Secrets are masked in tool summaries, error traces and record values before they reach the prompt, the room log, Slack or an export. Redaction is partial: names and timestamps still appear, and redacted tool summaries do reach your Claude endpoint. Alerts, logs and record values reach the model only inside an untrusted wrapper.

Runs where your pipeline runs

Self-hosted: a Docker image, Docker Compose, a Helm chart or Terraform for GCP. Sign-in with OIDC, with member, viewer and auditor roles. Credentials are set per pipeline, from environment variables or files. Claude runs through the Anthropic API, AWS Bedrock or Google Vertex AI, with token and cost budgets per room and per pipeline.

Your application is ready to send.

Can Claude change my pipeline?

Not by itself. Its tools are read-only. A fix runs only after every owner of the layers it touches approves that exact proposal, and only when write mode is on. It is off by default. If you list an action under auto_approve for a pipeline, a matching proposal gets a visible countdown that the driver or an owner can cancel; it still needs write mode on. The list is empty unless you configure it.

Where does my data go?

Piperoom runs in your environment. Redacted tool summaries go to the Claude endpoint you configure. If you connect Slack, it gets one outbound thread per room.

Which systems does it read?

PostgreSQL sources through Debezium on Kafka Connect, Kafka, Confluent Schema Registry, and Postgres, Snowflake, BigQuery, Databricks SQL or ClickHouse warehouses. Batch rooms read Airflow 2.x and dbt.

Is it open source?

No. The source is published for viewing only, and all rights are reserved.
