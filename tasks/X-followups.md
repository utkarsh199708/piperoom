# X wave: open gaps and follow-ups

The X wave (KAN-414 to KAN-458, epic KAN-413, plan `X-WAVE-DELIVERY-PLAN.md`) shipped in nine batches of about
five tickets, each reviewed by a lead and merged through PRs #842, #845, #846, #847, #848, #852, #855, #860, #861.
The code is merged; the wave's exit criteria are not all met. This file lists what is still open, then the
follow-ups each lead review recorded, by batch and owner (§2 of `AGENTS.md`). An owner picks up its own items; a
contract item goes to the leads.

## Open gaps (exit criteria not met)

1. **No live runs.** No X ticket's integration test, devctl break or scenario was run against the dev stack or
   Docker (the builders had none). Every `-tags integration` test compiles; none ran outside CI.
2. **Synthesised scenarios.** The X1e (silent corruption) and X2e (recovery) scenarios are synthesised
   (`RECORDED: NO`). They must be re-recorded on the dev stack, and their live 2-of-3 / 3-run checks done. The
   generators that produced them are kept under `tasks/x-wave/gen/` (build tag `xwavegen`, never built by CI): copy
   a directory into a `cmd/` folder and drop the tag to run it.
3. **CDC baseline not re-recorded.** `kafka_dup_keys` and `debezium_snapshot_progress` are now in every scenario's
   tool list; the recorded CDC baseline (and so every pass-rate comparison against it) may have moved.
4. **Non-Postgres warehouses** (Snowflake, ClickHouse, BigQuery, Databricks) have no Reconciler and no
   ColumnReader, so no drift checks, column lineage, column-set check or PII tags there (C3).
5. **Web lags the server** (A6): tuning preview and performance verdict, PII and column tags, edge columns,
   config_risks/retention, config_drift and accept-config, page-team button, config-versions UI, per-step recovery
   progress.
6. **Watcher state is per process** (A7): drift cooldown, column-set baseline, config_drift baseline, fingerprints
   reset at restart; accept-config works only on the watcher's leader.
7. **Owners leftovers** (A3): `vendor_status_url`, `watch.db_size_limit`, `forecast`/`config_drift` in
   knownSignals; `alertin.StatusPoller` is not wired in `cmd/server` (A5/C5).
8. **Multi-replica limits** (A5): page-team in-flight marker per replica; OpenLineage action events only for rooms
   the leader holds.
9. **Agent verification blocks steers** (A4): recovery verify (up to 10 min) and performance verify (17 to 30 min)
   hold the run; steers wait.
